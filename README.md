# FingerDrums — 指ドラムマシン

`index.html` 1ファイルだけで動く SPA の指ドラムマシン。フレームワーク・外部ライブラリ・音声ファイル・ビルド作業はすべて不要で、ブラウザで開けばそのまま遊べます。

▶ **デモ（GitHub Pages）: https://masawo2024.github.io/FingerDrums/**

## 特徴

- **PC**: キーボードを叩いて発音（グリッドに応じて `1 2 3 4` / `Q W E R` / `A S D F` / `Z X C V`）
- **スマホ**: 画面のパッドをタップして発音（マルチタッチ対応＝複数指で同時に叩ける）
- **パッドの大きさを 3 段階で切替**（**2×2 / 3×3 / 4×4**）。スマホなら 2×2・3×3 で指2本の連打がしやすくなります
- **音色の割り当ては自由**。パッドを選んで音色をタップするだけ。**同じ音色を複数のパッドに割り当てることも可能**
- **入れ替え**: ドラッグ（スマホは長押し→ドラッグ）で 2 つのパッドを交換
- グリッドごとに別々の配置を記憶。設定はすべて自動保存される
- **体感ラグを極限まで削った設計**（下記「遅延対策」参照）
- ドラム音は **Web Audio API による完全シンセサイズ**。読み込み待ちゼロ・音声アセット不要
- 出力デバイスの選択、音声の再接続、**体感遅延の実測（タップ式キャリブレーション）** を内蔵

## パッドの大きさ（グリッド）とキー割り当て

フッタの **`2×2` / `3×3` / `4×4`** でパッド数を切り替えられます。グリッドが小さいほどパッドは大きくなります（スマホで指2本の連打をしやすくするため）。

| グリッド | パッド数 | キー |
|---|---|---|
| `4×4` | 16 | `1 2 3 4` / `Q W E R` / `A S D F` / `Z X C V` |
| `3×3` | 9 | `1 2 3` / `Q W E` / `A S D` |
| `2×2` | 4 | `1 2` / `Q W` |

キーは常に**画面の並び（左上から）と同じ形**になるよう対応しています。グリッドごとに別の配置を保存するので、切り替えても設定は失われません。

### 初期配置

| グリッド | 左上 → 右下 |
|---|---|
| `4×4` | KICK / 808 / SNARE / CLAP / CH / OH / PH / CRASH / TOM L / TOM M / TOM H / RIDE / RIM / SHAKE / BELL / TAMB |
| `3×3` | KICK / SNARE / CH / CLAP / TOM M / OH / RIM / CRASH / RIDE |
| `2×2` | KICK / SNARE / CH / OH |

## 音色の割り当て／入れ替え（配置モード）

ヘッダの **「配置」** を押すと配置モードになります。

### 音色を割り当てる（重複も自由）

1. 割り当てたい **パッドをタップ**（オレンジの枠が付きます）
2. 下に出る **音色パレット** から鳴らしたい音色をタップ
3. すぐにその音色が鳴って確認できます。同じ音色を何個のパッドに置いても OK（パレットの `×2` は「いま何個のパッドで使っているか」）

### 2つのパッドを入れ替える

- **PC**: 入れ替えたいパッドをそのままドラッグして、別のパッドの上で離す
- **スマホ**: パッドを **長押し（450ms）→ そのままドラッグ**。短いタップでは動きません（誤操作防止）
- モード中もタップ／キー入力で音を試聴できます
- 「リセット」で**そのグリッドの初期配置**に戻ります。「完了」でモード終了
- 配置はグリッドごとに `localStorage` に保存され、次回も同じ配置で開きます

### キーは「枠」に固定、動くのは音色

割り当ては **枠（画面の位置）に対して行う** 方式です（MPC のパッドアサインと同じ）。キーのラベルは枠に固定なので、**キーボードの物理配置と画面の対応は崩れません**。

例：`3×3` で `2`（SNARE）の枠に `CRASH` を割り当てると、`2` を押すと CRASH が鳴ります。音色の名前と色も一緒に変わります。

## 体感遅延の実測（タップ式キャリブレーション）

ヘッダの **「計測」** を押すと 450ms 間隔（133BPM）のクリックが鳴ります。それに合わせて好きなパッドを同じリズムで叩くと、**実際に音が耳に届くまでの遅れ**を計測できます。

- 計測中はパッドの発音はミュートされます（自分の音が基準に混ざらないように）
- 一定間隔のクリックに合わせて叩くと、人は「聴こえた時刻」に合わせるため、`タップ時刻 − クリック予定時刻` の平均 ≒ 実測の合計遅延になります
- これは `AudioContext` の API 値（`base + outputLatency`）では**見えない HDMI/TV/Bluetooth 内部の処理遅延まで含みます**
- 結果は `localStorage` に保存され、バッジに表示されます（出力デバイスを変更・再接続すると自動的に無効化されます）

### 遅延の目安

| 構成 | 体感遅延の目安 |
|---|---|
| Bluetooth イヤホン | 150〜350ms（指ドラムには厳しい） |
| HDMI → TV | 30〜100ms超 |
| Android 中〜低価格帯（内蔵／有線） | 50〜90ms |
| Android 上位機（内蔵／有線） | 25〜50ms |
| PC + HDMI（モニター内蔵） | 30〜100ms超 |
| iPhone / iPad（内蔵／有線） | 15〜30ms |
| PC + アナログ/USB | 10〜30ms |

※ 実測値には**入力側の遅延**（キーボード 5〜15ms / スマホのタッチ 20〜60ms）も含まれます。

## 遅延対策として実装していること

1. **バッファ事前レンダリング** — 起動時に16音すべてを合成して `AudioBuffer` 化。発音時はバッファ再生のみで信号生成の計算はゼロ
2. **最短の入力経路** — `click` ではなく `pointerdown` / `keydown` を直接使用。`touch-action:none` でスクロール・ズーム判定も排除
3. **最小バッファ** — `latencyHint: 0` を要求（実測で `0.02` や `playback` の半分になることを確認済み）
4. **発音は 1 ノードだけ** — パッド音量をバッファに焼き込み、`createBufferSource → connect → start()` のみ。ヒットごとのノード生成1個・コールバック0で GC やメインスレッドのブレを最小化
5. **遅延ゼロのリミッター** — コンプレッサ（ルックアヘッド遅延あり）を使わず、`WaveShaperNode` による飽和カーブで最大出力を 1.0 に収める。オフライン測定でノード遅延は **0サンプル**（`2x`/`4x` オーバーサンプリングは 14サンプル遅れるため `none` を使用）
6. **出力ストリームを温め続ける** — 聴感上無音（-100dBFS）の微小ノイズを常時再生し、無音時にOSが音声出力を省電力化して初発音が遅れるのを防止
7. **サンプルレートを強制しない** — 端末のネイティブレートのまま動かす（Android で低遅延パスに乗るための条件）

## 使い方

```
index.html をブラウザで開くだけ（ローカルファイル可）
```

初回のタップ／キー入力でオーディオが有効になります（ブラウザの自動再生ポリシー対応）。

## 構成

```
index.html   # すべて（HTML + CSS + JS + ドラム音源のシンセシス）
```

## 動作確認済み

- Chrome / Edge（Windows, 48kHz）
- 全16パッドの発音、キーボード・タッチ・マルチタッチ、出力デバイス切替、再接続、キャリブレーション
- グリッド切替（2×2 / 3×3 / 4×4）：パッド数の増減、キー割り当て、各グリッドの配置保持、旧形式（4×4）の設定の引き継ぎ
- 配置モード：音色パレットからの割り当て（同一音色の重複可）、マウスドラッグ／長押しドラッグでの入れ替え、リセット、リロード後の復元、再接続後の整合
- 360〜412px 幅のスマホ表示でレイアウト崩れなし（2×2 / 3×3 / 4×4 すべて）
- スマホ幅の実寸パッド：360px 幅で 4×4=80px / 3×3=108px / 2×2=165px
